# 内嵌游戏、选帧与接管（首版）

## 配套版本

编辑器：`artifacts/windows-editor-04/KinokoTAS.App.exe`（源码 2981a59）。
游戏程序：
`C:/WorkSpace/6kinoko-modern/runtime-builds/modern-windows-tas-bridge-01/6kinoko-modern-windows-x64-94aefb79/kinoko_modern_gpu.exe`。
必须选择支持 KTAS1 的这版或更新兼容程序，旧版只有 CLI 回放参数，不能连接。
游戏 DAT、fonts、shaders 仍与游戏 EXE 同目录；不复制到编辑器会话。

## 操作

1. 打开 `.krec` 后点“打开游戏回放”，选择上述游戏程序。
   普通录制 `record/session.krec` 和本编辑器分支会自动寻找 `initial/`；
   外部文件/项目则要求选择录制开始前的存档快照目录。无存档时选空目录。
   旧版本录制会提示逐帧验证，检查值不同则停止，不绕过状态验证。
2. 首帧显示后保持暂停。点时间轴左侧帧号，或输入帧号并“定位”。
   “上一帧/下一帧”在连接回放时也定位游戏；点击动作格仍只编辑项目。
3. “播放/暂停/逐帧”控制实际模拟。图像显示的是第 N 帧完成后的状态；
   协议用已完成帧数 N+1，界面同时显示画面帧与逻辑帧，传输短暂滞后时不假装同步。
4. “从此帧接管”先暂停，再切换实时输入。点“播放”后点击画面获得焦点。
   方向键移动，Z 跳跃/确认，X 攻击/加速/搬运，A 暂停/副确认，C 道具；
   Space 仅跳跃、Enter 仅确认、Esc 暂停。暂停时可在画面保持按键并按 F10 推进一帧。
   面板失焦释放全部输入，整个编辑器失焦还会请求暂停。
5. “结束并保存分支”会让游戏完成录制尾部，再自动打开分支文件。
   原始录制和存档均保持不变。新分支完整包含接管前已验证输入和接管后操作。
6. “新建录制”从空存档启动，首帧暂停；使用相同输入和保存流程。

## 会话与限制

会话在编辑器 EXE 旁 `sessions/session-.../`：`initial/` 保存初始小文件，
`source.krec` 是源录制，`session.json` 描述身份，每次启动都有新的 `run-.../`。
每个运行目录中 `saves/`、`branch.krec`、`replay-status.txt`、`bridge/` 分开。
所有分支和失败日志保留。新录制不会导回普通游戏存档。

首版选帧按正常模拟速度到达目标；回退重启独立游戏进程并恢复初始存档后重播。
尚无完整状态快照、瞬时倒带或倍速。定位过程中可按“暂停”取消继续定位。
接管后请先结束并保存，再打开新分支进行回退定位。

`.ktas` 的输入格修改仍保存为编辑意图，不自动注入本次源录制回放。
本版“接管录制”是生成新有效输入/状态分支的路径，不伪造编辑后的检查值。
音乐暂未和工具暂停状态联动；普通启动不启用桥接或 GPU 读回。
目前本机只验证 Windows 自动接口与合成 GPU 画面；实际游玩由用户验证。

## 协议与实现

本机独立目录 KTAS1 v1，使用 C++ filesystem + C# FileStream，无 OS 窗口嵌入。
控制文件 `command.txt` 为 `sequence verb argument`，verbs：target（完成帧数）、
run、pause、takeover、stop。状态为 `KTAS1 sequence completed total phase`。
Pause/target/takeover 的确认在游戏帧边界产生；编辑器等待相同请求序号。
输入文件是递增编号和19位动作掩码；1秒无更新自动释放输入。

SDL GPU 隐藏窗口下渲染至 640x480 RGBA8 离屏纹理，复制至下载缓冲，等待 GPU
fence 后发布 `image.rgba`。头为8字节 KTASIMG1、uint64完成帧数、uint32宽高，
然后是紧密RGBA像素，均little-endian。帧号随渲染队列传递，不根据到达时间猜测。
临时文件完成后替换信箱；读者允许删除共享并重试缺失。信箱文件复用，磁盘占用有界，
但本版同步GPU读回和文件传输可能影响TAS实时速度，后续可替换为共享内存/管道。

每个会话只控制自己启动的进程。退出请求超时会终止该子进程，不宣称损坏分支有效。
引擎退出代码不是录制成功依据：保存后必须再次通过完整 .krec 解析。
